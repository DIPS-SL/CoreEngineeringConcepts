Every Request Needs a Route
Before any code runs, something must decide which machine answers. Routing is the front door of every system.
🌍
Think Globally
100M users on six continents can't all hit one data center. Traffic must land close to home, then fan out smartly.
🧊
No Hero Machines
A healthy system survives any single server dying mid-request. Servers are cattle, not pets.
🎒
Stateless Wins
When servers remember nothing about users, any server can answer anything — and scaling becomes trivial.
🚀
Why routing matters
Facebook peaks at millions of HTTP requests every second. No machine on Earth can absorb that alone — so a routing stack of GeoDNS, load balancers, and API gateways slices the flood into streams that ordinary servers can drink. We will build that stack, tier by tier.

The gateway is a traffic cop, not a worker
It routes, authenticates, and rate-limits — but never runs business logic. Clients see one clean front door; behind it, hundreds of microservices can be added, moved, or replaced without any client noticing.
🎙
Stateless Services Key Distinction
Load balancing only works if any server can handle any request. That requires servers that remember nothing.
😰 Stateful — session in server RAM
📌Your login session lives in Server 2's memory — the balancer must "pin" you to Server 2 forever (sticky sessions).
⚡Server 2 gets overloaded? Tough — your requests can't move.
💥Server 2 crashes? You're logged out mid-scroll. So is everyone else pinned there.
😎 Stateless — session in Redis / JWT
🎒Session lives in a shared store (Redis) or travels inside a signed token (JWT). Servers keep nothing local.
🔀Request 1 → Server 3, request 2 → Server 8. Nobody cares. Any server, any request.
🗑A server crashes? The balancer stops sending it traffic. Zero users notice.

Statelessness is what makes load balancing actually work
A load balancer with stateful servers is a traffic cop directing cars that can only park in one specific spot. Move all user state into shared stores, and every server becomes interchangeable — that's the moment scaling turns into simply adding machines.

Key Takeaways
What every engineer should know about traffic routing and load balancing.
⚖️
Load Balancer
Spreads requests across many identical servers. Health checks evict dead machines within seconds — failures become invisible.
🌍
Multi-Tier Routing
GeoDNS picks the data center. L4 spreads raw TCP. L7 gateway reads the URL. Each tier narrows one decision — fast checks first.
🚪
API Gateway
One front door for all clients: path routing, auth, rate limiting. Microservices stay hidden and can evolve freely behind it.
🎒
Stateless Services
No local memory of users — session state lives in Redis or JWTs. Any server handles any request, so servers become disposable.
💡
The rule of thumb
Scale out, not up. One giant server always melts eventually; many disposable servers behind a balancer never do — but only if they're stateless. Make every server forgettable, and adding capacity stops being engineering and starts being shopping.
