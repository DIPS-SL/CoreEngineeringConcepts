The hybrid rule: threshold-based routing
If a user has more than ~10,000 followers, treat them as a celebrity. Skip the fan-out cache writes. Instead, merge their posts into each follower's feed at read time. For everyone else, Kafka pushes pre-computed feeds. Instagram, Twitter, and LinkedIn all use variants of this approach.
🎙
Key Takeaways
What every engineer should know about feed generation at scale.
📬
Fan-out on Read
Simple to implement. DB query at feed-load time. Works for small scale. Breaks catastrophically when users follow thousands of accounts.
✉️
Fan-out on Write
Push post to every follower's cache immediately. Reads are instant — ~5ms. But one celebrity post fans out to 380M writes. Expensive.
⚡
Kafka Queue
Decouples post creation from feed delivery. Durable, ordered, scalable. Workers drain the queue asynchronously. Publisher never blocks.
🧬
Hybrid Model
Route by follower count. Regular users get fan-out-on-write. Celebrities get fan-out-on-read merged at request time. Best of both worlds.
💡
The rule of thumb
Start with fan-out on read. It's simple and correct. Move to fan-out on write with Kafka when feed latency becomes the pain point. Add the celebrity hybrid only when you can measure the write amplification cost. The same post that costs 1 write at 30 followers costs 380 million writes for Kylie Jenner — that asymmetry is your engineering signal.
